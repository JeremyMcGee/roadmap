# Requirements Document

## Introduction

A command-line utility that reads draw.io XML files (specifically those generated by the MarkdownToDrawio tool, containing horizontal category swimlanes and vertical quarter columns) and produces a Markdown file in the exact format expected by MarkdownToDrawio as input. The tool infers each activity's category and quarter by determining which swimlane row and quarter column contains the activity node based on its geometric position in the XML. This enables a round-trip workflow: generate a diagram from markdown, manually edit the diagram in draw.io (moving activities, adding or removing nodes and edges), then regenerate the markdown to reflect changes.

## Glossary

- **CLI**: The command-line interface application that accepts arguments and executes the Draw.IO-to-Markdown conversion
- **Drawio_Parser**: The component responsible for reading draw.io XML (mxGraphModel format) and extracting structural elements (swimlanes, quarter columns, activity nodes, edges)
- **Activity_Node**: An mxCell element with style containing "rounded=1;whiteSpace=wrap;html=1" and vertex="1", representing a roadmap activity
- **Swimlane**: An mxCell element with style containing "shape=swimlane;horizontal=0" and vertex="1", representing a horizontal category band with its value attribute holding the category label
- **Quarter_Column**: A vertical region in the diagram bounded by quarter separator lines, with a label mxCell (id starting "qlabel_") holding the quarter text (e.g., "Q1 2025")
- **Quarter_Separator**: An mxCell element with id starting "qsep_" representing a vertical dashed line that delimits quarter column boundaries
- **Dependency_Edge**: An mxCell element with edge="1" and source/target attributes, representing a directed dependency between two Activity_Nodes where the source is the antecedent and the target is the dependent
- **Position_Resolver**: The component responsible for determining which Swimlane and Quarter_Column an Activity_Node belongs to, based on the node's geometry coordinates relative to swimlane and quarter column boundaries
- **Markdown_Generator**: The component responsible for producing the output Markdown file from the resolved activities, in the format expected by the MarkdownToDrawio tool
- **Roadmap_Model**: The internal representation containing all activities with their inferred labels, quarters, categories, and dependency relationships

## Requirements

### Requirement 1: Parse Draw.IO XML Structure

**User Story:** As an architect, I want the tool to parse draw.io XML files containing swimlane diagrams, so that I can extract roadmap structure from diagrams I have edited in draw.io.

#### Acceptance Criteria

1. WHEN the CLI receives a valid draw.io XML file path, THE Drawio_Parser SHALL read the file and navigate the mxfile/diagram/mxGraphModel/root element hierarchy to locate all mxCell elements
2. WHEN the XML contains mxCell elements with style containing "shape=swimlane;horizontal=0" and vertex="1", THE Drawio_Parser SHALL extract each element as a Swimlane with its value attribute as the category label and its mxGeometry (x, y, width, height) as the bounding region
3. WHEN the XML contains mxCell elements with id starting "qlabel_" and vertex="1", THE Drawio_Parser SHALL extract each element as a Quarter_Column label with its value attribute as the quarter text and its mxGeometry x-coordinate and width as the column boundaries
4. WHEN the XML contains mxCell elements with style containing "rounded=1;whiteSpace=wrap;html=1" and vertex="1", THE Drawio_Parser SHALL extract each element as an Activity_Node with its value attribute as the label (after stripping HTML tags and decoding HTML entities) and its mxGeometry as the position
5. WHEN the XML contains mxCell elements with edge="1" and both source and target attributes present, THE Drawio_Parser SHALL extract each element as a Dependency_Edge linking the source Activity_Node to the target Activity_Node
6. IF the input file does not exist at the specified path, THEN THE CLI SHALL exit with a non-zero exit code and print an error message to standard error indicating the file was not found
7. IF the input file contains content that is not valid XML, THEN THE CLI SHALL exit with a non-zero exit code and print an error message to standard error indicating the XML is malformed
8. IF the XML file does not contain the expected mxfile/diagram/mxGraphModel/root structure, THEN THE CLI SHALL exit with a non-zero exit code and print an error message to standard error indicating the file is not a recognized draw.io diagram

### Requirement 2: Resolve Activity Positions to Categories and Quarters

**User Story:** As an architect, I want the tool to infer each activity's category and quarter from its position in the diagram, so that manually repositioned activities are correctly classified.

#### Acceptance Criteria

1. WHEN an Activity_Node's vertical center (y-coordinate of geometry plus half its height) falls within the y-range of exactly one Swimlane's geometry, THE Position_Resolver SHALL assign that Swimlane's category label to the Activity_Node
2. WHEN an Activity_Node's horizontal center (x-coordinate of geometry plus half its width) falls within the x-range of exactly one Quarter_Column (defined by the column label's x-coordinate to x-coordinate plus width), THE Position_Resolver SHALL assign that Quarter_Column's quarter text to the Activity_Node
3. IF an Activity_Node's vertical center does not fall within any Swimlane's y-range, THEN THE Position_Resolver SHALL assign the Activity_Node to the Swimlane whose vertical midpoint has the minimum absolute distance to the node's vertical center, selecting the first Swimlane in document order if two or more Swimlanes are equidistant
4. IF an Activity_Node's horizontal center does not fall within any Quarter_Column's x-range, THEN THE Position_Resolver SHALL assign the Activity_Node to the Quarter_Column whose horizontal midpoint has the minimum absolute distance to the node's horizontal center, selecting the first Quarter_Column in document order if two or more Quarter_Columns are equidistant
5. IF an Activity_Node's vertical center falls within the y-range of more than one Swimlane, THEN THE Position_Resolver SHALL assign the Activity_Node to the Swimlane whose vertical midpoint has the minimum absolute distance to the node's vertical center, selecting the first Swimlane in document order if two or more Swimlanes are equidistant
6. IF an Activity_Node's horizontal center falls within the x-range of more than one Quarter_Column, THEN THE Position_Resolver SHALL assign the Activity_Node to the Quarter_Column whose horizontal midpoint has the minimum absolute distance to the node's horizontal center, selecting the first Quarter_Column in document order if two or more Quarter_Columns are equidistant
7. WHEN no Swimlanes are found in the XML, THE CLI SHALL exit with a non-zero exit code and print an error message to standard error indicating that no category swimlanes were detected
8. WHEN no Quarter_Columns are found in the XML, THE CLI SHALL exit with a non-zero exit code and print an error message to standard error indicating that no quarter columns were detected

### Requirement 3: Resolve Dependency Relationships

**User Story:** As an architect, I want the tool to extract dependency arrows between activities, so that the generated markdown reflects the correct prerequisite relationships.

#### Acceptance Criteria

1. WHEN a Dependency_Edge has a source attribute matching an Activity_Node identifier and a target attribute matching a different Activity_Node identifier, THE Drawio_Parser SHALL record a directed dependency where the source Activity_Node is the antecedent and the target Activity_Node is the dependent
2. WHEN a Dependency_Edge references a source or target identifier that does not correspond to any recognized Activity_Node, THE Drawio_Parser SHALL discard that edge without producing an error and continue processing remaining edges
3. WHEN multiple Dependency_Edges share the same source Activity_Node identifier and the same target Activity_Node identifier, THE Drawio_Parser SHALL record exactly one dependency for that ordered source-target pair
4. WHEN an Activity_Node has no incoming Dependency_Edges after all edges are resolved, THE Roadmap_Model SHALL contain an empty set of antecedents for that Activity_Node
5. IF a Dependency_Edge has a source attribute equal to its target attribute, THEN THE Drawio_Parser SHALL discard that self-referencing edge and continue processing remaining edges

### Requirement 4: Generate Roadmap Markdown Output

**User Story:** As an architect, I want the tool to produce markdown in the exact format expected by the MarkdownToDrawio tool, so that I can round-trip between diagram and documentation.

#### Acceptance Criteria

1. WHEN the Roadmap_Model is populated with one or more resolved activities, THE Markdown_Generator SHALL produce a Markdown file beginning with a level-1 heading "# Dependency Documentation" followed by a blank line
2. THE Markdown_Generator SHALL render each activity as a level-2 heading using the exact activity label text, with activities ordered in ascending lexicographic order by label using ordinal string comparison
3. THE Markdown_Generator SHALL render three level-3 sub-sections under each activity in this fixed order: "### Depends on", "### Quarter", "### Category", each preceded by a blank line
4. WHEN an activity has one or more dependencies, THE Markdown_Generator SHALL render each dependency as a bullet-list Markdown link in the format "- [Antecedent Label](#anchor)" where the anchor is derived by lowercasing the label, removing characters that are not alphanumeric, whitespace, or hyphens, and replacing one or more whitespace characters with a single hyphen, with dependencies sorted in ascending lexicographic order by antecedent label using ordinal string comparison
5. WHEN an activity has zero dependencies, THE Markdown_Generator SHALL render the text "No dependencies" on the line following the blank line after the "### Depends on" heading
6. THE Markdown_Generator SHALL render the quarter value as a non-empty text line following a blank line after the "### Quarter" heading
7. THE Markdown_Generator SHALL render the category value as a non-empty text line following a blank line after the "### Category" heading
8. IF an activity in the Roadmap_Model has a null or empty quarter value, THEN THE Markdown_Generator SHALL report an error indicating the activity label and the missing quarter, and SHALL NOT produce output
9. IF an activity in the Roadmap_Model has a null or empty category value, THEN THE Markdown_Generator SHALL report an error indicating the activity label and the missing category, and SHALL NOT produce output
10. THE Markdown_Generator SHALL produce output that, when processed by the MarkdownToDrawio tool's Markdown_Parser, yields a Roadmap_Model with the same set of activity labels, quarter assignments, category assignments, and dependency relationships as the source Roadmap_Model

### Requirement 5: Command-Line Interface

**User Story:** As an architect, I want to run the tool from the command line with simple arguments, so that I can integrate it into my workflow and scripts.

#### Acceptance Criteria

1. THE CLI SHALL accept an input draw.io XML file path as a required positional argument
2. THE CLI SHALL accept an output file path as an optional second argument
3. WHEN no output file path is provided, THE CLI SHALL write the output to a file named the same as the input file with a .md extension in the same directory
4. WHEN the CLI is invoked with no arguments or with a help flag (-h or --help), THE CLI SHALL print usage instructions to standard output that include the accepted arguments and their descriptions, and exit with a zero exit code
5. IF the output directory does not exist, THEN THE CLI SHALL exit with a non-zero exit code and print an error message to standard error indicating the output directory was not found
6. WHEN the output file already exists at the resolved output path, THE CLI SHALL overwrite the existing file without prompting
7. WHEN the CLI completes conversion successfully, THE CLI SHALL write the output file and exit with a zero exit code
8. IF the output file path cannot be written due to a permission error, THEN THE CLI SHALL exit with a non-zero exit code and print an error message to standard error indicating the file could not be written

### Requirement 6: Round-Trip Parsing Support

**User Story:** As a developer, I want a pretty-printer for the Roadmap_Model and round-trip validation, so that I can verify parsing and generation correctness.

#### Acceptance Criteria

1. WHEN given a Roadmap_Model, THE Drawio_Parser SHALL produce a draw.io-compatible XML string in mxGraphModel format that, when parsed back into a Roadmap_Model, contains the same set of Activity labels (compared case-sensitively), the same Category assignment per Activity, the same Quarter assignment per Activity, and the same set of dependency relationships per Activity (compared as unordered sets of antecedent labels)
2. FOR ALL valid draw.io XML inputs produced by the MarkdownToDrawio Diagram_Generator, WHEN the XML is parsed into a Roadmap_Model and that model is used to generate Markdown via the Markdown_Generator, THEN parsing that Markdown with the MarkdownToDrawio Markdown_Parser SHALL yield a Roadmap_Model that is equivalent to the intermediate model on Activity labels (case-sensitive), Quarter values (case-insensitive), Category values (case-insensitive), and dependency sets (unordered, case-insensitive label comparison)
3. THE Markdown_Generator SHALL produce output that is byte-for-byte identical to the output of the MarkdownToDrawio Markdown pretty-printer when given a Roadmap_Model with the same Activity labels, Quarter values, Category values, and dependency sets
4. FOR ALL valid Roadmap_Model objects containing between 1 and 500 Activities where each Activity has a non-empty label of at most 200 characters, a non-empty Quarter, a non-empty Category, and between 0 and 50 dependency labels, WHEN the model is printed to Markdown using the Markdown_Generator and that Markdown is parsed with the MarkdownToDrawio Markdown_Parser, THEN the resulting Roadmap_Model SHALL contain the same Activity labels, the same Quarter value per Activity, the same Category value per Activity, and the same dependency label sets per Activity as the original model
5. IF the draw.io XML input contains Activity nodes with duplicate labels (two or more nodes sharing the same label text after whitespace normalization), THEN THE Drawio_Parser SHALL treat each unique label as a single Activity and merge their dependency sets into one combined set for that label
